# 2.10 智能商贸提单助手 - 原始需求规格与系统框架

## 1. 架构总览与核心策略（用户输入）

- **数据底座**：业务单据采用 MongoDB，非标物料简称纠错采用 Milvus 向量近似检索，架构原生解耦；
- **AI 提取与省 Token 策略**：采用两阶段漏斗（LLM 仅提取实体参数 JSON，耗费极少 Token；后续标准编码映射交由 Milvus 向量检索秒级匹配），从根本上避免将海量物料字典塞入 Prompt；
- **前端双模态一致性**：基于 Zustand 全局单源真相，全屏与悬浮窗仅是不同的渲染容器，切换时草稿数据、输入流、指标卡片零延迟、零丢失；
- **履约核验与超额流转**：支持正常订单直接生效；超额触发红标预警，录入追加说明后支持生成“待特批订单”流转。

## 2. 需求规格正文 (摘自选定实战项目需求规格说明书 2.10)

### 2.10.1 开发范围

| 业务领域 | 核心功能范围与能力说明 |
| :--- | :--- |
| **基础能力** | 用户身份鉴权、会话生命周期管理、操作审计记录、草稿暂存与载入、系统参数配置 |
| **智能提单能力** | 自然语言意图理解、多轮对话实体抽取、单据图像 OCR 识别与字段结构化、Excel 表格批量解析、物料简称纠错与标准化物料编码映射 |
| **履约核验能力** | 合同主数据关联、采销订单关联合验、合同剩余可下订单数与金额动态核算、超额风险预警、必填字段缺失提示 |
| **商贸协同能力** | 订单草稿一键生成、预览区字段双向同步、一键正式提单、订单详情抽屉回查、订单列表筛选联动与状态更新 |
| **双模态交互能力** | 商贸业务系统内嵌悬浮窗（Floating Widget）、独立全屏提单工作台（Fullscreen Workbench）、视图双向无缝切换 |

### 2.10.2 用户角色与权限

| 角色类型 | 职责说明与权限边界 |
| :--- | :--- |
| **`业务经办人`** | 发起文本对话提单、上传单据图片、上传批量表格、核对与修改草稿、一键提交订单、查询本人与本部门订单 |
| **`业务审批人`** | 查看待审订单详情、核对合同额度与超额预警提示、执行订单审核、退回修改或驳回 |
| **`系统管理员`** | 维护商贸合同主数据与物料编码字典、配置 AI 模型调用参数、配置额度校验规则、查看系统操作审计日志 |

> **⚠️ 权限隔离规则**  
> 提单与提交操作强制校验用户登录态与所属经办部门，禁止越权操作非授权部门单据。

### 2.10.3 页面需求

#### 1. 全屏提单工作台
- **多模态提单交互区**：支持文本对话、单据图片上传 OCR 识别、Excel 表格批量解析三个输入面板切换，提供快捷操作标签（新建销售订单、新建采购订单、继续上次、使用帮助）与消息气泡流
- **订单草稿预览与核验区**：实时呈现草稿状态胶囊（草稿未提交/待确认/已提交）、合同履约额度四项统计指标卡片、超额预警横幅、基本信息网格卡片、产品明细表格与一键提单操作栏

#### 2. 商贸系统内嵌悬浮窗
- **商贸订单列表集成区**：嵌入底层商贸销售与采购订单列表，提供多维条件筛选与订单详情滑出抽屉
- **右下角智能提单悬浮窗**：点击右下角悬浮球展开，支持收起、全屏切换、快捷多轮对话提单与数据双向联动

#### 3. 批量导入与数据中心页
- 提供批量 Excel 订单导入模板下载、拖拽上传、多行数据解析校验表格、异常行红标预警与批量并发提交

#### 4. 主数据与系统配置页
- 维护销售/采购合同台账、标准化物料编码映射库、公允价与履约配额阈值、大模型调用参数

### 2.10.4 业务规则与履约核验体系

#### 📝 自然语言提取与实体补全规则
- 提取描述文本中的合同编号、工程项目、物资品名、规格、吨数及交期要求
- 自动填充固定业务属性（业务名称为“国内传统贸易”、采购模式为“直发”、业务标签为“传统贸易”）
- 依据当前登录身份自动绑定经办人、经办单位、创建人与创建时间
- 关键必填要素缺失时在预览区高亮标记待确认状态，并在对话流中主动发起澄清提示

#### 🔍 单据图像识别与物料纠错规则
- 支持发货签收单、磅单、采购合同等单据图片 OCR 结构化提取
- 针对手写体、俗称与非标简称，自动匹配系统物料词库并纠错映射为标准物料编码与规范名称

#### 💰 合同履约配额与超额校验规则
- 关联查询合同累计已下订单数、累计已下金额、剩余可下订单数及剩余可下金额
- 当次订单金额超出合同剩余可用额度时，触发硬性超额警告提示，要求经办人复核并记录预警标识

#### 🛑 提单防重与幂等规则
- 订单正式提交成功后锁定提交按键，防止网络抖动导致的重复提交
- 生成唯一商贸单据流水编号（如 `XSDD-WZGS-20260318-001`），并将草稿状态推进为已提交

### 2.10.5 前端模块要求
- **`双模式切换引擎`**：管理全屏模式与悬浮窗模式的状态同步、视图切换与路由跳转
- **`多模态输入交互组件`**：支持文本输入、图片拖拽识别预览、Excel 文件解析导入的三面板平滑切换
- **`订单预览与高亮模块`**：负责订单草稿卡片、物资明细表格、合同额度统计卡片的动态渲染与异常字段高亮
- **`批量校验与处理模块`**：负责表格数据的逐行解析、异常行状态标记、单行微调采纳与批量提交
- **`商贸系统集成模块`**：负责与底层商贸系统订单列表、详情抽屉的事件通信与数据联动刷新

### 2.10.6 后端模块要求
- **`对话理解服务`**：负责会话上下文装配、自然语言理解、商贸意图识别与订单实体抽取
- **`多模态解析引擎`**：负责单据图片 OCR 识别、物料编码标准化映射、Excel 表格批量解析与格式校验
- **`主数据与额度计算中心`**：负责合同与工程项目主数据检索、合同累计履约额度核算与动态超额判定
- **`订单流转引擎`**：负责订单草稿暂存、提交校验、正式订单生成、幂等防重控制与状态流转
- **`商贸对接模块`**：负责向商贸业务子系统同步正式订单与物资明细记录

### 2.10.7 核心业务流程

#### 流程 1：自然语言对话提单流程
1. 经办人在工作台或悬浮窗输入自然语言提单需求
2. 对话引擎抽取合同号、项目、物料、数量与期望交期
3. 系统关联商贸合同主数据，补全签约单位、送货地址与经办信息
4. 系统计算合同剩余额度并实时装配订单草稿预览卡片
5. 经办人核对草稿并补充必要字段
6. 点击一键提单，系统生成正式订单编号并写入商贸数据库

#### 流程 2：单据图片 OCR 提单流程
1. 经办人上传发货签收单或合同单据图片
2. OCR 服务提取物资名称、规格、数量与到货单位
3. 语义纠错模块将物料简称自动校准为标准物料编码与规范名称
4. 系统输出识别提取卡片并同步至订单预览区
5. 经办人确认无误后点击一键提单

#### 流程 3：Excel 批量提单流程
1. 经办人上传包含多笔采购/销售订单的 Excel 文件
2. 系统按行并发解析并校验合同号与数量规范
3. 界面展示批量明细列表，对异常行标注预警状态
4. 经办人针对异常行进行行内核实修改
5. 点击批量提交，系统并发创建正式商贸订单

### 2.10.8 单据输出与履约追溯格式
- **`订单结构化主档`**：包含单据编号、单据类型（销售/采购）、合同编号、签约单位、工程项目、收货地址、联系人、经办人、创建时间与订单状态
- **`物资产品明细表`**：包含序号、标准物料编码、规范物资名称、品牌规格、主计量数量、主计量单位、含税单价、总金额与履约进度
- **`合同履约配额看板`**：包含合同总金额、累计已下订单金额、本次占用金额、剩余可下额度及超额预警标记
- **`操作审计与追溯流水`**：包含操作人、操作动作（草稿保存/图片识别/正式提单）、输入原文本/图像哈希、生成单据号与时间戳

### 2.10.9 示例业务场景

#### 场景 1：建筑钢材大宗销售订单自然语言提单
- 经办人输入“给中建八局科技城项目下 200 吨 HRB400E 螺纹钢，走 2026-WZ-089 合同，后天送到一号工地”；
- 系统自动提取关键实体并关联销售合同主数据，匹配出标准物料编码 `STL-RB-400E-20`；
- 系统核算合同剩余额度充足，自动生成销售订单草稿；
- 经办人确认后一键提单，生成正式销售订单。

#### 场景 2：纸质发货签收单拍照提单与超额预警
- 经办人上传一张纸质发货签收单照片，系统 OCR 识别出“42.5 水泥 500 吨，金额 22 万元”；
- 系统比对采购合同发现该合同剩余可下单金额仅剩 15 万元，系统在预览区顶部标红弹出超额警告横幅；
- 经办人核实确认属于项目追加采购并备注说明后提交，系统生成待特批订单。
