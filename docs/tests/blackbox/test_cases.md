## 一、 测试背景与依据规范

### 1.1 测试目标
本测试用例全集面向 **TradeDoc AI 智能商贸提单助手**，依据业务需求、技术架构及高保真原型规约，针对**步骤 7（侧滑审批抽屉与中台双向数据闭环）**以及**步骤 9（黑盒业务全场景穿刺 Case A~E）**进行端到端黑盒用例设计。
测试覆盖前端交互、后端 API 规则引擎、中台沙箱 (Mock ERP) 台账联动与外部数据库原子持久化，确保系统在商贸流通实战场景下的可靠性、数据一致性及纯商贸语言合规性。

## 三、 步骤 7：侧滑审批抽屉业务流专项测试用例

### TC-STEP7-01: 待特批单据唤起侧滑抽屉与视图渲染
- **前置条件**：ERP 订单列表已展示一笔状态为 `PENDING_SPECIAL_APPROVAL`（待特批审核）的超额单据（如关联合同 `2026-WZ-089`，金额 ¥800,000.00）。
- **测试步骤**：
  1. 经办人/审批人进入 ERP 订单中心页面 (`/erp`)；
  2. 在订单表格操作列定位待特批单据行，点击“审核流转”操作按钮；
  3. 观察界面右侧滑出动效及遮罩层。
- **预期结果**：
  1. 右侧平滑滑出宽度为 720px 的详情抽屉（`OrderDetailDrawer`），左侧底层商贸页面半透明毛玻璃遮罩；
  2. 抽屉顶栏清晰呈现标题“商贸订单详情与审批核查”、订单流水号以及红底醒目的“待特批审批 (超额预警)”状态胶囊；
  3. 点击遮罩层或右上角“X”图标可正常关闭抽屉。

### TC-STEP7-02: 动态合同履约 4 项指标看板核验
- **前置条件**：通过 TC-STEP7-01 打开待特批订单详情抽屉。
- **测试步骤**：
  1. 查看抽屉顶部“关联合同履约配额动态核验”看板；
  2. 检查 4 个指标卡片数值与后端合同台账实时计算结果：
     - **合同总金额**：`contract_total_amount`（如 ¥ 5,000,000）
     - **累计已执行金额**：`accumulated_order_amount` 及占用百分比
     - **剩余可用额度**：`remaining_quota_amount`
     - **本次申请金额**：`current_order_amount`
  3. 检查第四张卡片底部的超额警示信息。
- **预期结果**：
  1. 看板自动调用 `GET /api/contracts/{contract_no}/quota` 获取最新数值，无延迟闪烁；
  2. 当本次申请金额超出剩余可用额度时，指标卡片标红高亮，明确计算并展示“超额差额 ¥ X,XXX.XX”；
  3. 看板右上角提示“⚠️ 合同剩余额度不足 · 触发特批流转”。

### TC-STEP7-03: 经办人追加特批申报理由说明卡片核验
- **前置条件**：通过 TC-STEP7-01 打开包含特批说明的单据抽屉。
- **测试步骤**：
  1. 查阅指标看板下方的“业务经办人追加特批理由说明”黄色警示卡片；
  2. 核对申报人姓名、所属部门、申报日期及经办人填写的特批事由；
  3. 查验卡片底部的证明附件信息。
- **预期结果**：
  1. 卡片展示经办人身份信息（如“申报人：李强 (物资贸易一部) ｜ 申报时间：2026/9/28”）；
  2. 引号内完整展示申报理由原话（如“科技城数字经济产业园二期抢工期急需追加高规格钢材储备”）；
  3. 呈现附件名称（如“科技城项目工期提前追加采购备忘录_盖章扫描件.pdf”），并具备可点击的“[查阅原件]”交互。

### TC-STEP7-04: 快捷批注选项联动与输入框双向绑定
- **前置条件**：抽屉处于待特批审批状态，展示“审批裁决批复意见 (业务审批主管专用)”区域。
- **测试步骤**：
  1. 查验界面提供的 3 个快捷短语按钮：
     - `+ 同意并特批放行`
     - `+ 同意但限额执行`
     - `+ 需补签补充协议`
  2. 依次点击不同的快捷短语；
  3. 观察下方批注文本框 (`textarea`) 的内容变化；
  4. 手动在文本框中补充或修改文字。
- **预期结果**：
  1. 点击任意快捷短语，文本框内容即时 100% 替换为对应的高标准合规风控批注范本；
  2. 文本框支持二次键入与自由编辑；
  3. 若清空文本框点击提交，前端弹出校验提示“请填写审批裁决批复意见”，阻止提交。

### TC-STEP7-05: 审批通过 (PASS) 状态机流转与额度原子扣减
- **前置条件**：当前抽屉订单为待特批订单，合同累计金额为 ¥4,850,000，订单金额为 ¥200,000。
- **测试步骤**：
  1. 在批注框填入“经核实，现场保供需求属实，增补备忘录真实有效，准予特批放行本笔订单”；
  2. 点击抽屉右下角蓝色“审批通过并生效单据”按钮；
  3. 观察前端交互与网络请求 (`POST /api/orders/{order_no}/approve`，action: PASS)；
  4. 查看后台订单状态及中台合同剩余配额。
- **预期结果**：
  1. 提交过程中按钮呈现 Loading 禁用态，提交成功后抽屉自动关闭并弹出通过通知；
  2. 本地数据库中该订单状态变更为 `ACTIVE`，审批人记录为“陈总监”，审批批注落盘；
  3. 模拟中台订单状态变更为 `AUDITED` 或 `COMPLETED`；
  4. 合同台账可用额度原子扣减 ¥200,000，累计下单金额更新为 ¥5,050,000。

### TC-STEP7-06: 退回修改 (RETURN) 状态机流转
- **前置条件**：当前抽屉展示待特批订单。
- **测试步骤**：
  1. 点击“退回经办人修改”按钮；
  2. 批注填写“请补充项目业主签收联与增补备忘录盖章件后再报”；
  3. 点击确认执行退回流转 (`POST /api/orders/{order_no}/approve`，decision: RETURN)。
- **预期结果**：
  1. 抽屉关闭，订单状态变更为 `RETURNED`；
  2. 模拟中台订单状态变更为 `RETURNED`，并保留退回批注意见；
  3. 合同可用配额与已用额度保持原样，不发生扣减；
  4. 经办人在工作台重新载入时可对该单据进行补充修改。

### TC-STEP7-07: 审批驳回 (REJECT) 状态机流转
- **前置条件**：当前抽屉展示待特批订单。
- **测试步骤**：
  1. 点击红色的“审批驳回 (作废单据)”按钮；
  2. 批注填写“超额比例过高且未补充增补合同协议，存在重大法律风控敞口，予以驳回终结”；
  3. 确认执行驳回流转 (`POST /api/orders/{order_no}/approve`，decision: REJECT)。
- **预期结果**：
  1. 订单状态变更为 `REJECTED`，中台状态变更为 `REJECTED`；
  2. 合同配额无损，不产生任何扣减；
  3. 单据生命周期终结作废，不再允许二次提交或审批。

### TC-STEP7-08: 审批完成列表无刷新局部静默更新
- **前置条件**：经办人处于 ERP 订单列表页。
- **测试步骤**：
  1. 记录列表首行待审订单编号与“待特批超额单”统计计数；
  2. 在抽屉中完成审批通过 (PASS) 裁决；
  3. 观察抽屉关闭后宿主列表组件的刷新行为。
- **预期结果**：
  1. 抽屉成功提交后派发全局事件 `window.dispatchEvent(new CustomEvent('erp:order_refresh'))`；
  2. 页面无需全局 F5 刷新，局部静默重新拉取 `/api/erp/orders`；
  3. 顶部“待特批超额单”数量即时 -1，“履约中总金额”即时累加；
  4. 该单据状态胶囊无缝切换为绿色的“履约已生效”。

### TC-STEP7-09: 已归档单据只读模式查验
- **前置条件**：选择一笔已生效 (`ACTIVE`) 或已驳回 (`REJECTED`) 的历史订单。
- **测试步骤**：
  1. 在列表点击“查看单据”；
  2. 观察打开的抽屉内容。
- **预期结果**：
  1. 顶部状态胶囊正确显示“履约已生效”或“已驳回作废”；
  2. 审批操作区变为只读历史记录卡片，展示历史审批人姓名、所属部门与历史批注意见；
  3. 底部仅呈现“关闭抽屉”按钮，隐藏所有审批操作按键，杜绝重复审批。

## 四、 步骤 9：黑盒业务全场景穿刺 (Case A~E) 测试用例

### TC-CASE-A: Case A 正常提单直接生效全链路穿刺
- **业务场景**：华夏石化框架合同项下，按公允市场价采购一批标准规格管材，合同配额充裕，无任何违规项。
- **输入要素**：
  - 合同编号：`2026-WZ-090`（华夏石化销售集团，总额 1000 万，剩余 800 万）
  - 物资品名：无缝钢管 (`PIP-SM-20G-57`)
  - 规格型号：`20G Φ57*3.5`
  - 采购数量：100.0 米
  - 含税单价：120.00 元/米
  - 申报金额：12,000.00 元
  - 特批说明：空 (无需特批)
- **执行动作**：调用 `POST /api/orders/submit`（直接生效提单）。
- **断言与预期结果**：
  1. 合规风控诊断级别为 `PASS`，`is_over_quota` 为 `false`；
  2. 返回 code 200，生成统一流水号 `XSDD-WZGS-YYYYMMDD-XXX`；
  3. 订单状态直接推进为 `ACTIVE`；
  4. 合同可用额度精确原子扣减 ¥ 12,000.00；
  5. 模拟中台订单即刻同步生成，状态为 `AUDITED`。

### TC-CASE-B: Case B 高价预警拦截、说明补全特批提报与审批放行
- **业务场景**：现场紧急采购，提报单价超出基准指导价公允区间 (+29.2%)，触发价格偏离风控预警。
- **输入要素**：
  - 合同编号：`2026-WZ-090`
  - 物资品名：无缝钢管 (`PIP-SM-20G-57`，基准指导价 120.00 元)
  - 提报单价：155.00 元/米（偏离 +29.2%）
  - 采购数量：10.0 米
- **执行动作**：
  1. 第一阶段：未填特批说明，尝试调用 `POST /api/orders/submit` 直接生效；
  2. 第二阶段：补全特批说明“因现场紧急保供抢工期，加价采购特级合金无缝管，特申请领导特批放行”，调用 `POST /api/orders/submit-special`；
  3. 第三阶段：审批主管调用 `POST /api/orders/{order_no}/approve` (decision: PASS)。
- **断言与预期结果**：
  1. 第一阶段返回 code 400，拦截提示“单据存在价格偏离等风控预警，直接生效受限，须填写不少于10字说明走审批流程”；
  2. 第二阶段成功提交，订单状态为 `PENDING_SPECIAL_APPROVAL`，中台标记待审，暂不扣减额度；
  3. 第三阶段审批通过后，订单状态推进为 `ACTIVE`，中台变更为 `COMPLETED`/`AUDITED`，额度正式扣减。

### TC-CASE-C1: Case C1 合同超额硬拦截与特批流转
- **业务场景**：远大钢铁年度合同剩余可用额度仅为 ¥150,000.00，当次申请采购 200 吨钢筋，金额达 ¥800,000.00，超额 ¥650,000.00。
- **输入要素**：
  - 合同编号：`2026-WZ-089`
