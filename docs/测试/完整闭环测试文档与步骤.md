### 场景一：正常销售提单直接生效全链路闭环 (Case A)

#### 1. 业务目标
验证合规采购/销售指令输入后，系统完整执行“实体抽取 -> 规范品名对齐 -> 履约额度核算 -> 正式提单 -> 中台回写 -> 额度原子扣减”的全生命周期。

#### 2. 前置测试数据
- **关联合同**：`2026-WZ-089`（科技城项目大宗钢材供应合同，额度充裕，剩余额度 > ¥1,000,000）
- **操作人员**：`李强`（物资贸易一部）

#### 3. 浏览器 UI 实操步骤
1. 打开浏览器访问 `http://127.0.0.1:5173/workbench`；
2. 在左侧**自然语言提单**聊天框内输入以下指令并按回车：
   > `给中建八局下200吨400E 20圆钢，走2026-WZ-089合同，单价4000元送至一号工地`
3. **查验工作台左侧与右侧联动**：
   - 助手气泡回复提单要素解析摘要；
   - 右侧【提单草稿核对与编审】区域自动填入：
     - 签约客户：`中建八局科技城项目部`（或标准客户全称）
     - 关联合同：`2026-WZ-089`
     - 送货地址：`一号工地`
     - 物资明细：`热轧带肋钢筋 HRB400E Φ20mm`、数量 `200.00` 吨、单价 `4000.00` 元、总额 `¥800,000.00`
   - 顶部指标看板：【剩余可用配额】显示充足，本次合规诊断呈现绿色【额度充足 合规】徽标；
4. 点击右下方蓝色【一键正式提单】按钮：
   - 按钮呈现 Loading 状态，携带唯一幂等键发起请求；
   - 顶部弹出绿色通知：`正式提单成功！订单编号：XSDD-WZGS-20260928-XXX，已同步回写ERP系统`；
   - 草稿状态转换为【履约已生效 (ACTIVE)】，按钮自动锁定防重提交；
5. 点击左侧导航栏【销售订单大盘 (`/erp`)】：
   - 订单列表首行实时呈现最新提交的订单流水号，状态显示绿色【履约已生效】；
   - 关联客户、品名、金额均与工作台完全一致。

#### 4. 判定通过标准
- [x] 前端表单无任何硬编码假数据，数据 100% 来源于自然语言解析；
- [x] 成功生成 `XSDD-` 前缀的正式销售订单单号；
- [x] 合同 `2026-WZ-089` 的已执行金额增加 `¥800,000.00`，剩余配额同步减少 `¥800,000.00`。

### 场景二：合同超额硬拦截与中台特批审批流转闭环 (Case C1 + 步骤 7)

#### 1. 业务目标
验证订单金额超过合同剩余可用额度时触发风控硬拦截；经办人录入特批理由提报；业务主管在 ERP 大盘通过侧滑抽屉完成审核并推进订单生效。

#### 2. 前置测试数据
- **关联合同**：`2026-WZ-089`（假设剩余额度为 ¥400,000.00）
- **超额提单金额**：¥800,000.00（超额 ¥400,000.00）

#### 3. 浏览器 UI 实操步骤
1. 进入提单工作台 `http://127.0.0.1:5173/workbench`；
2. 输入超额提单指令：
   > `走2026-WZ-089合同，采购300吨HRB400E螺纹钢，单价4200元，配送至科技城项目部`（总金额 ¥1,260,000.00）；
3. **查验风控预警横幅**：
   - 顶部看板【本次合规诊断】显示红色【超额需特批】徽标；
   - 草稿表单上方弹出红色警示横幅：`⚠️ 合同履约超额预警：合同剩余额度不足，超出额度 ¥XXX，无法直接提单`；
   - 右下角提单按钮自动转变为红色【提交超额特批申请】；
4. **特批拦截核验**：
   - 若未填特批理由直接点击【提交超额特批申请】，系统提示：`请补充超额特批申请理由（不少于10个汉字）`，提交动作被硬性拦截；
5. **补录特批申报理由**：
   - 在特批说明框内输入：`科技城项目二期抢工期急需追加高规格钢材储备，已经商贸分管总批示同意`；
   - 再次点击【提交超额特批申请】；
   - 弹出绿色提示：`超额特批申请已提交！单号：XSDD-WZGS-20260928-XXX，进入业务主管待审流`；
   - 订单状态标记为黄色【待特批审核 (PENDING_SPECIAL_APPROVAL)】，合同额度此时**不预扣**；
6. **进入 ERP 大盘执行审批 (步骤 7 侧滑抽屉)**：
   - 切换到【销售订单大盘 (`/erp`)】；
   - 在列表首行找到该笔黄色【待特批审核】单据，点击右侧操作列【审核流转】按钮；
   - 界面右侧平滑滑出 **720px 审批抽屉 (OrderDetailDrawer)**；
   - 核验抽屉内 4 项动态指标看板（明确显示超额差额）及经办人特批事由卡片；
   - 在【审批裁决批复意见】区点击快捷批注【同意特批，按合同追加备忘录执行】；
   - 点击绿色【审核通过生效】按钮；
   - 抽屉自动关闭，底层列表该订单即时静默刷新为绿色【履约已生效】，关联合同额度正式扣减。

#### 4. 判定通过标准
- [x] 未填或特批理由少于 10 字时绝对拦截，无法提交；
- [x] 特批提报成功后，在审核通过前合同额度不扣减；
- [x] 审批通过后，订单状态流转为 `ACTIVE` / `AUDITED`，合同额度正确原子扣减。

## 四、 终端一键 cURL 穿刺校验脚本

若需要在无图形界面的服务器或终端快速验证全闭环，可直接复制执行以下脚本：

```bash
#!/usr/bin/env bash
set -e

echo "=== [1/4] 验证主数据与合同配额 ==="
CONTRACT_JSON=$(curl -s http://127.0.0.1:8000/api/contracts/2026-WZ-089/quota)
echo "合同配额: $CONTRACT_JSON"

echo -e "\n=== [2/4] 自然语言智能解析 ==="
PARSE_JSON=$(curl -s -X POST http://127.0.0.1:8000/api/parse/chat \
  -H "Content-Type: application/json" \
  -d '{"text": "向中建八局供200吨400E 20圆钢，走2026-WZ-089合同，单价4000元送一号工地"}')
echo "解析结果: $PARSE_JSON"

echo -e "\n=== [3/4] 正式提单一键提交 (带幂等键) ==="
IDEM_KEY="IDEM-$(date +%s%N)"
SUBMIT_JSON=$(curl -s -X POST http://127.0.0.1:8000/api/orders/submit \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $IDEM_KEY" \
  -d '{
    "order_type": "SALES",
    "contract_no": "2026-WZ-089",
    "counterparty_name": "中建八局科技城项目部",
    "project_name": "科技城数字经济产业园",
    "delivery_address": "一号工地",
    "business_name": "国内传统贸易",
    "procurement_mode": "直发",
    "business_tag": "传统贸易",
    "items": [{
      "material_code": "MAT-STEEL-002",
      "material_name": "热轧光圆钢筋 HPB300",
      "specification": "Φ20mm",
      "unit": "吨",
      "quantity": 200,
      "unit_price": 4000,
      "total_amount": 800000
    }],
    "total_amount": 800000,
    "operator_name": "李强",
    "operator_dept": "物资贸易一部"
  }')
echo "提交响应: $SUBMIT_JSON"
ORDER_NO=$(echo $SUBMIT_JSON | grep -o '"order_no":"[^"]*' | cut -d'"' -f4)

echo -e "\n=== [4/4] 验证中台台账同步与配额扣减 ==="
ERP_ORDER=$(curl -s http://127.0.0.1:8001/api/erp/orders/$ORDER_NO)
echo "中台订单状态: $ERP_ORDER"
```
